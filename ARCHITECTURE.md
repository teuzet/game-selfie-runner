# Архитектура SelfieRunner

Забег 4 бегунов (люди или боты) от быка по улице ~5 минут, lockstep-мультиплеер через Unity Relay. Unity 6 (6000.3), URP, Windows/Steam, клавиатура.

## Слои
| Сборка | Что внутри | Зависит от |
|---|---|---|
| `Game.Core` (netstandard2.1) | вся логика забега: бегуны, бык, препятствия, толчки, зрители, донаты, квесты, подсказки чата, боты, сборка улицы | ничего |
| `Game.Net` (netstandard2.1) | lockstep-протокол: буфер входов, задержка ввода, сверка хэшей, подмена отвалившегося игрока ботом; транспорт — интерфейс `ITransport` | `Game.Core` |
| `Unity/` | рендер, камера-фронталка, лица, анимации, UI стрима, тексты чата, звук; транспорт Relay + Lobby | обе |

Логики в Unity нет: `Update()` копит время, по фиксированному шагу зовёт `Simulation.Step`, затем читает состояние и события для рендера.

## Ядро
- `Simulation(RaceConfig, seed)` → `Step(TickInputs)`, 30 тиков/с, забег ≈ 9000 тиков.
- `RaceState` — всё состояние, сериализуемо и копируемо (`Clone()`, `StateHash()`). Копируемость нужна под возможный rollback.
- `RaceConfig` — сид, улица и по `CharacterId` на каждое место (выбор персонажа в лобби до старта; у бота характер задаёт и персонажа по умолчанию).
- `TickInputs` — по входу на каждое из 4 мест: руль (−1/0/+1), кнопки действий (толчок, подножка; набор уточнит `design/overview.md`). Место бота заполняет сам `Simulation`, вход снаружи для него игнорируется.
- `RaceEvents` — список событий тика для Unity: столкновение, бык рядом, затоптали, толкнул/сбил, влез в кадр, квест выдан/выполнен, донат, подсказка («препятствие X слева через N тиков», с шумом). Unity из событий делает чат, эмоции лица и звук.
- Математика: `Fixed` (Q16.16 на `int`/`long`), свой `DetRandom` (xorshift/PCG) от сида забега, без `float`, `DateTime`, порядка `Dictionary`/`HashSet`.

## Улица и физика
- В ядре улица плоская: координата `s` (метры вдоль) и `x` (сдвиг поперёк). Участок — данные: длина, ширина в начале/конце, уклон, тип (прямая, спуск, подъём, площадь с фонтаном, пруд, рынок, арка, финиш-арена).
- Высота живёт только в Unity (сплайн + профиль высот); в ядре уклон лишь меняет скорость.
- Улица на забег собирается по сиду из заготовленных участков, препятствия расставляются по правилам участка. Набор участков и правила — данные (JSON в `Game.Core/Data/` или подаются при создании `RaceConfig`) — решение по ходу.
- Своя 2D-физика: бегуны — круги, препятствия — прямоугольники/круги, бык — капсула. Столкновение с препятствием = спотыкание (потеря скорости, короткий стан); толчок = импульс по `x`; затоптали = «нет сигнала» на N тиков, бегун встаёт позади быка. Без физики Unity, рэгдоллов и прыжков.
- Бык движется вдоль `s` со скоростью, подтягивающейся к толпе (резинка), чтобы дистанция оставалась напряжённой. Числа — в `design/overview.md`.

## Сеть (lockstep)
- Хост собирает входы всех мест и рассылает пакет тика; задержка ввода подстраивается под пинг (старт 3 тика ≈ 100 мс). Каждые 30 тиков машины шлют `StateHash`; расхождение = десинк, логируем и останавливаем забег.
- Отвалился игрок — его место с текущего тика ведёт бот того же характера, реконнекта в M1 нет.
- Лобби по коду: Unity Lobby + Relay, транспорт — Unity Transport. Netcode for GameObjects не используем. Steamworks — M2.
- Rollback не делаем в M1; если руль онлайн ощущается ватным, добавляется поверх (`Clone()` уже есть).
- Проект Unity Gaming Services создаёт Nick один раз (инструкция появится с фичей сети).

## Персонажи
- Персонаж — набор чисел (данные): максимальная скорость и разгон, устойчивость к толчкам и спотыканиям, множитель прироста зрителей, «вкусность» для быка, длительность «нет сигнала». Примеры из концепта: гламурная блондинка — зрителей больше, бежит медленнее (каблуки); спортсмен в красной майке — быстрее всех, но бык предпочитает его.
- Все параметры читает ядро: скорость в движении, множитель в экономике, «вкусность» в выборе цели быка (бык целится не просто в ближайшего, а по взвешенной дистанции — ближе и вкуснее). Балансные числа — в `design/overview.md`.
- Персонаж и характер бота независимы: любой характер может бежать любым персонажем. Визуальная часть персонажа (голова, одежда, селфи-палка) — ассеты Unity, привязаны по `CharacterId`.

## Боты
- `IBotBrain.Decide(RaceState, seat) → PlayerInput`, детерминированные, внутри ядра.
- Боты знают только то, что знал бы игрок на их месте (подсказки своего чата с тем же шумом) — решение по ходу, если без подглядывания они слишком глупые.
- Характер = параметры (данные: желаемая дистанция до быка, агрессия к соседям, реакция на подсказки, интерес к квестам) + небольшой код поведения. M1: «трус», «адреналинщик», «тролль».

## Unity
- Позиция бегуна в мире = сплайн улицы(`s`) + сдвиг(`x`) + высота профиля; между тиками интерполяция.
- Камера своего бегуна — фронталка селфи-палки (смотрит назад). Если на экране нужны чужие стримы, это миниатюры низкого разрешения с пониженной частотой — решение по ходу с геймдизайнером.
- Лицо — 3D-голова из частей (форма, причёска, нос, очки, усы) плюс сменные глаза, брови и рот под эмоции (ужас, восторг, злорадство). Этот же набор частей потом даёт кастомизацию.
- UI стрима (чат, зрители, донаты, эмодзи, квесты) — uGUI/UI Toolkit, решение по ходу.

## Контент: данные и код
- Данные: участки улицы и правила препятствий, персонажи, характеры ботов, типы квестов и их параметры, база сообщений чата.
- База чата: JSON по поводам (событие ядра → пачка фраз с весами), многоязычный формат с ключом языка; M1 по-русски, английский в M2. Фразы генерируются заранее (тул `brainstorm`), в рантайме LLM нет. Текст косметический, по сети не синхронизируется.
- Код: правила движения, столкновений, экономики зрителей и донатов, поведения ботов, протокол сети.

## Ассеты
`Unity/Assets/Art/` — модели, материалы, анимации, UI-спрайты; берём из библиотеки `factory_kit` где есть, перекрашиваем под `art/style.md`. Данные контента рядом со своим потребителем (`Game.Core/Data/`, `Unity/Assets/Data/`).

## Тесты
- `Game.Core.Tests`: детерминизм (два прогона одного сида и входов → равные хэши на каждом тике), полный забег 4 ботов за секунды, запись и проигрывание входов, юнит-тесты физики, экономики, квестов.
- `Game.Net.Tests`: 4 клиента в одном процессе на фейковом транспорте с задержкой, джиттером и потерями; хэши сходятся, отвал игрока → бот.
- Метрики баланса из прогонов ботов (сколько раз затоптан каждый характер, распределение донатов) — для геймдизайнера.
- `Unity/Assets/Tests`: EditMode-тесты адаптеров (маппинг `s,x` → мир, события → чат).
