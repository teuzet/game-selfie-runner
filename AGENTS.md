# Как устроен этот репозиторий

- `Game.Core/` — детерминированное игровое ядро на чистом C# (тесты на .NET 8+, ядро — netstandard2.1 для Unity, без Unity). Собирается и тестируется `dotnet build` / `dotnet test`.
- `Game.Core.Tests/` — xUnit-тесты ядра. Каждая фича добавляет тесты сюда.
- `Unity/` — Unity-проект, который только рендерит состояние ядра и собирает ввод. Логики в Unity нет. Ассеты артиста — в `Unity/Assets/Art/`.
- `design/` — визитка (`overview.md`) и диздоки фич (`F-xxx.md`); пишет геймдизайнер, ревьюит продюсер.
- `art/` — `style.md` и превизы в `refs/`; пишет продюсер. `brainstorm/` — сырые ответы тула brainstorm.
- `features.json` — список фич; правит только техлид. Исполнители меняют лишь свой статус через диспетчер.
- `decisions.md` — решения, принятые агентами без Nick, с причинами и откатом.
- `discuss-later.md` — вопросы, на которые ответа Nick не дождались; взят рекомендованный вариант.
- `progress.md` — что влито в main и когда.
- `.factory/` — служебные файлы диспетчера (result.json, review.json, feedback.md, answer.json). Не коммитить.

## Правила для всех
- Детерминизм: без `DateTime.Now`, `Random` без сида, порядка Dictionary/HashSet в логике. Для дробей — `Fixed`.
- Один исполнитель — одна фича — одна ветка `feat/F-XXX`.
- Меняй только файлы из `owned_files` своей фичи.
